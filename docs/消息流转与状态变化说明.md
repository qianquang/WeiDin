# 消息流转与状态变化说明

## 📋 快速参考：接收方在线 vs 不在线

| 场景 | 接收方在线 | 接收方不在线 |
|------|-----------|-------------|
| **消息推送** | ✅ SignalR 实时推送成功 | ❌ SignalR 推送失败（但消息已保存） |
| **接收时机** | ⚡ 立即接收（毫秒级） | 🔄 上线后接收 |
| **接收方式** | 📡 SignalR 事件推送 | 📡 HTTP API 查询 |
| **未读提示** | 🔴 立即显示未读红点（私聊和群聊） | 🔴 上线后显示未读数量（私聊和群聊） |
| **消息显示** | ✅ 实时显示在聊天窗口 | ✅ 打开会话时加载 |
| **状态记录（私聊）** | ✅ 发送方：Sent<br>⏳ 接收方：待标记已读 | ✅ 发送方：Sent<br>❌ 接收方：无（直到上线） |
| **状态记录（群聊）** | ✅ 发送方：Sent<br>✅ 所有成员：Sent（发送时已创建） | ✅ 发送方：Sent<br>✅ 所有成员：Sent（发送时已创建，即使不在线） |
| **用户体验** | 📱 即时通讯体验 | 💾 离线消息存储 |

**核心区别**：
- **在线**：消息通过 SignalR 实时推送，用户立即看到
- **离线**：消息保存在数据库，用户上线后主动拉取
- **群组消息特殊处理**：发送时为所有成员创建状态记录，确保离线成员上线后能正确统计未读数量

---

## 一、消息状态定义

系统定义了三种消息状态，存储在 `MessageStatus` 表中：

| 状态 | 说明 | 默认值 |
|------|------|--------|
| **Sent** | 已发送 | 消息创建时的默认状态 |
| **Delivered** | 已送达 | 接收方设备收到消息 |
| **Read** | 已读 | 接收方已查看消息 |

**重要说明**：
- 每个消息对每个用户都有独立的状态记录（`MessageId` + `UserId` 唯一）
- 状态存储在分表中：`MessageStatus_{relationId}`（按 `RelationId` 分表）
- 状态只能由接收方更新（发送方不能标记自己的消息为已读）

---

## 二、消息完整流转流程

### 阶段 1：消息发送（发送方）

**流程**：
1. 用户输入消息并点击发送
2. 前端通过 HTTP API 发送消息到后端
3. 后端处理：
   - 从 JWT 获取发送方 ID
   - 如果 `ReceiverId` 未设置且非群组消息，通过 `RelationId` 查询 `Friendship` 获取接收方 ID
   - 保存消息到数据库分表：`Message_{relationId}`
   - 为发送方创建状态记录（`Status = "Sent"`）
4. **群组消息特殊处理**：
   - 如果是群组消息，为所有群成员（除了发送者）创建状态记录
   - 状态记录初始状态为 **Sent**，即使成员不在线也会创建
   - 确保每条消息+每个成员一条状态记录（`MessageId` + `UserId` 唯一）
5. 补全发送者信息（昵称、头像）
6. 通过 SignalR 实时推送：
   - **私聊消息**：发送给接收方的 SignalR 组
   - **群组消息**：发送给群组所有成员的 SignalR 组

**注意**：SignalR 推送失败不影响消息保存（消息已持久化）

---

### 阶段 2：消息接收（接收方）

**重要**：根据接收方是否在线，消息流转方式完全不同。

---

#### 场景 A：接收方在线

**判断条件**：接收方已建立 SignalR 连接，且在 `user_{receiverId}` 组中

**流程**：

1. **SignalR 实时推送**
   - 后端通过 SignalR 将消息推送给接收方
   - 推送成功，接收方立即收到消息

2. **前端接收处理**
   - 接收方通过 SignalR 事件接收消息
   - 立即添加到消息列表
   - 更新会话的最后消息
   - 如果当前不在查看该会话（私聊和群聊都支持），增加未读计数

3. **UI 显示**
   - 侧边栏立即显示未读红点（私聊和群聊都支持）
   - 消息列表自动滚动到底部（如果正在查看该会话）
   - 实时显示消息内容、发送者、时间

**特点**：
- ⚡ **实时性**：消息几乎瞬间到达
- 📱 **即时通知**：用户无需刷新即可看到新消息
- 🔴 **未读提示**：立即显示未读红点（私聊和群聊）

---

#### 场景 B：接收方不在线

**判断条件**：接收方未建立 SignalR 连接，或不在 `user_{receiverId}` 组中

**流程**：

1. **SignalR 推送失败**
   - 后端尝试通过 SignalR 推送消息
   - 推送失败：接收方不在线，未连接
   - 但消息已保存到数据库

2. **消息存储状态**

   **私聊消息**：
   - 消息保存在数据库：`Message_{relationId}` 表
   - 状态记录：`MessageStatus_{relationId}` 表（`Status = "Sent"`，`UserId = 发送方ID`）
   - 接收方状态：**无接收方的状态记录**（因为接收方未收到消息）

   **群组消息**：
   - 消息保存在数据库：`Message_{relationId}` 表
   - 发送方状态记录：`MessageStatus_{relationId}` 表（`Status = "Sent"`，`UserId = 发送方ID`）
   - 所有成员状态记录：已为所有成员（除了发送者）创建状态记录（`Status = "Sent"`）
   - 即使成员不在线，状态记录也会被创建，确保上线后能正确统计未读数量

3. **接收方上线后的处理流程**

   **步骤 1：建立 SignalR 连接**
   - 用户建立 SignalR 连接
   - 加入个人 SignalR 组 `user_{userId}`
   - 更新在线状态为 true
   - 广播上线通知给好友

   **步骤 2：加载会话列表**
   - 加载好友列表和群组列表
   - 为每个会话查询未读消息数量（包括离线期间的消息）
   - 加载每个会话的最新一条消息
   - 在侧边栏显示未读红点（私聊和群聊都支持）

   **步骤 3：打开会话时加载消息**
   - 用户点击会话
   - 通过 HTTP API 查询消息列表（包括离线消息）
   - 后端查询 `Message_{relationId}` 表，关联查询 `MessageStatus_{relationId}` 表
   - 返回消息列表（包括离线期间收到的消息）

   **步骤 4：自动标记已读**
   - 切换会话时自动标记所有消息为已读（私聊和群聊都支持）
   - 通过 HTTP API 批量标记已读
   - 后端更新或创建状态记录（`Status = "Read"`）
   - 通过 SignalR 通知发送方消息已被读取

4. **前端状态更新**
   - 通过 HTTP API 加载消息列表（包括离线消息）
   - 消息添加到消息列表
   - 更新会话的最后消息
   - 未读计数在加载会话列表时已设置

5. **UI 显示**
   - 侧边栏显示未读红点（加载会话列表时已设置，私聊和群聊都支持）
   - 打开会话时加载并显示所有消息（包括离线消息）
   - 自动标记已读后，未读红点消失

**特点**：
- 💾 **持久化**：消息已保存在数据库，不会丢失
- 🔄 **延迟接收**：接收方上线后才能看到消息
- 📊 **批量加载**：通过 HTTP API 批量加载离线消息
- 🔴 **未读提示**：上线后立即显示未读数量（私聊和群聊）

---

#### 场景对比总结

| 特性 | 接收方在线 | 接收方不在线 |
|------|-----------|-------------|
| **消息推送** | ✅ SignalR 实时推送成功 | ❌ SignalR 推送失败 |
| **消息存储** | ✅ 保存到数据库 | ✅ 保存到数据库 |
| **接收时机** | ⚡ 立即接收 | 🔄 上线后接收 |
| **接收方式** | 📡 SignalR 事件 | 📡 HTTP API 查询 |
| **未读提示** | 🔴 立即显示 | 🔴 上线后显示 |
| **消息显示** | ✅ 实时显示 | ✅ 打开会话时加载 |
| **状态记录** | ✅ 发送方状态：Sent | ✅ 发送方状态：Sent<br>❌ 接收方状态：无（直到上线） |
| **已读标记** | ✅ 打开会话时自动标记 | ✅ 打开会话时自动标记 |

#### 在线状态判断机制

**后端在线状态管理**：
- 使用内存在线用户表：`UserId → 该用户所有活跃连接 ID 集合`
- 判断用户是否在线：检查是否有活跃连接
- 有连接即在线，无连接即离线

**上线流程**：
1. 用户建立 SignalR 连接
2. 加入 `user_{userId}` 组
3. 将连接 ID 加入在线用户字典
4. 如果是第一个连接，更新数据库 `IsOnline = true`
5. 广播上线通知给好友

**下线流程**：
1. SignalR 连接断开
2. 从在线用户字典移除连接 ID
3. 如果是最后一个连接，更新数据库 `IsOnline = false`
4. 广播下线通知给好友
5. 从 `user_{userId}` 组移除

**前端在线状态显示**：
- 连接时接收好友在线状态列表（批量推送）
- 实时接收单个好友上线/下线通知
- 在会话列表中显示好友在线状态（绿色圆点 = 在线，灰色 = 离线）

### 阶段 3：消息状态变化

#### 3.1 已送达（Delivered）- 可选

**触发时机**：接收方设备收到消息（可通过客户端自动触发）

**处理流程**：
1. 接收方通过 HTTP API 标记消息为已送达
2. 后端在 `MessageStatus_{relationId}` 表中插入或更新状态记录
3. 状态更新为 `Status = "Delivered"`，`UserId = 接收方ID`
4. 可选：通过 SignalR 通知发送方消息已送达

---

#### 3.2 已读（Read）- 核心功能

**触发时机**：
1. **自动触发**：用户切换到会话时
2. **手动触发**：用户点击消息或调用 API

**自动标记已读流程**：

1. **用户切换会话**
   - 清空未读计数
   - 自动标记该会话的所有消息为已读（私聊和群聊都支持）

2. **批量标记已读**
   - 前端通过 HTTP API 批量标记已读
   - 后端处理：
     - 查询所有未读消息（未删除）：
       - **私聊消息**：接收方是当前用户且发送方不是当前用户
       - **群组消息**：群组ID匹配且发送方不是当前用户，且（没有状态记录 || 有状态记录但状态不是Read）
     - 对每条消息：
       - 检查 `MessageStatus` 表是否已有记录（`MessageId` + `UserId`）
       - 如果有，更新 `Status = "Read"`
       - 如果没有，插入新记录 `Status = "Read"`
     - 返回所有已标记的消息 ID 列表
   - 通过 SignalR 通知所有相关消息的发送方

3. **单个消息标记已读**
   - 前端通过 HTTP API 标记单个消息为已读
   - 后端处理：
     - 验证消息存在且当前用户是接收方（不是发送方）
     - 在 `MessageStatus_{relationId}` 表中插入或更新状态记录
     - `Status = "Read"`, `UserId = 接收方ID`
   - 通过 SignalR 通知发送方

4. **发送方接收已读通知**
   - 发送方通过 SignalR 接收消息已读通知
   - 前端可更新消息状态显示

---

### 阶段 4：消息查询与显示

#### 4.1 加载会话列表

**流程**：
1. 加载好友列表和群组列表
2. 为每个会话创建会话对象
3. 为每个会话加载：
   - 最新一条消息
   - 未读消息数量（私聊和群聊都支持）

#### 4.2 加载消息列表

**流程**：
1. 用户点击会话
2. 自动标记已读
3. 通过 HTTP API 加载消息列表
4. 后端处理：
   - 查询 `Message_{relationId}` 表
   - 关联查询 `MessageStatus_{relationId}` 表，获取每条消息的状态列表
   - 返回消息列表，包含状态信息

#### 4.3 未读数量查询

**流程**：
1. 通过 HTTP API 查询未读数量
2. 后端处理：
   - **私聊消息**：查询接收方是当前用户且发送方不是当前用户的消息，排除已有 `Status = "Read"` 记录的消息
   - **群组消息**：查询群组ID匹配且发送方不是当前用户的消息，且（没有状态记录 || 有状态记录但状态不是Read），排除已有 `Status = "Read"` 记录的消息
3. 返回未读消息数量

## 四、关键数据结构

### 消息对象
- **消息ID**：唯一标识
- **RelationId**：分表标识（私聊 = ConversationId，群聊 = GroupId）
- **发送方ID**：消息发送者
- **接收方ID**：消息接收者（私聊）
- **群组ID**：群组标识（群聊）
- **消息类型**：Text / Image / Video / File
- **消息内容**：消息正文
- **创建时间**：消息发送时间
- **状态列表**：每条消息对每个用户的状态记录

### 状态对象
- **状态ID**：唯一标识
- **消息ID**：关联的消息
- **用户ID**：状态所属用户
- **状态**：Sent / Delivered / Read
- **创建时间**：状态创建时间

---

## 五、分表机制

系统使用 **按 RelationId 分表** 的策略：

- **消息表**：`Message_{relationId}`
- **状态表**：`MessageStatus_{relationId}`

**优势**：
- 每个会话的消息和状态独立存储
- 查询性能优化（只查询相关表）
- 便于数据迁移和清理

**RelationId 说明**：
- 私聊：`RelationId = ConversationId`（来自 `Friendship` 表）
- 群聊：`RelationId = GroupId`

---

## 六、未读计数逻辑

### 6.1 未读计数增加
- **时机**：收到新消息（SignalR `ReceiveMessage` / `ReceiveGroupMessage`）
- **条件**：
  - 当前不在查看该会话
  - 私聊和群聊都支持未读计数

### 6.2 未读计数清零
- **时机**：用户切换到会话
- **操作**：
  1. 清空未读计数
  2. 批量标记已读

### 6.3 未读计数查询
- **时机**：加载会话列表时
- **逻辑**：
  - **私聊消息**：查询接收方是当前用户且没有 `Status = "Read"` 记录的消息数量
  - **群组消息**：查询群组ID匹配且发送方不是当前用户，且（没有状态记录 || 有状态记录但状态不是Read）的消息数量

---

## 七、注意事项

1. **状态权限**：只有接收方可以更新消息状态（发送方不能标记自己的消息为已读）

2. **群聊未读**：群聊也支持未读红点功能
   - 群组消息发送时，为所有成员（除了发送者）创建状态记录（`Status = "Sent"`）
   - 即使成员不在线，状态记录也会被创建，确保上线后能正确统计未读数量
   - 点击群组会话时，自动标记所有未读消息为已读
   - 每条消息+每个成员一条状态记录（`MessageId` + `UserId` 唯一）

3. **SignalR 推送**：
   - ✅ **在线场景**：推送成功，接收方立即收到消息
   - ❌ **离线场景**：推送失败，但消息已持久化到数据库
   - ⚠️ **重要**：推送失败不影响消息保存，接收方上线后可通过 HTTP API 查询

4. **在线状态判断**：
   - 基于 SignalR 连接状态（内存在线用户字典）
   - 用户建立连接时加入用户组
   - 用户断开连接时从组中移除
   - 多设备/多标签页：只要有一个连接在线，用户即在线

5. **离线消息处理**：
   - 消息已保存在数据库，不会丢失
   - 接收方上线后，通过加载会话列表获取未读数量
   - 打开会话时，通过 HTTP API 批量加载离线消息
   - 自动标记已读后，未读计数清零

6. **状态同步**：
   - **在线场景**：前端通过 SignalR 实时接收消息和状态变化
   - **离线场景**：前端通过 HTTP API 查询消息和状态
   - 无需轮询，采用推送 + 查询的混合模式

7. **分表查询**：所有消息操作都需要 `RelationId` 参数，用于定位分表

8. **自动标记已读**：切换会话时自动标记所有消息为已读（私聊和群聊都支持）

9. **消息状态记录**：
   - **私聊消息**：
     - 发送消息时，只创建发送方的状态记录（`Status = "Sent"`）
     - 接收方不在线时，**不会创建接收方的状态记录**
     - 接收方上线后，打开会话时才会标记已读，此时创建接收方的状态记录（`Status = "Read"`）
   - **群组消息**：
     - 发送消息时，创建发送方的状态记录（`Status = "Sent"`）
     - 同时为所有成员（除了发送者）创建状态记录（`Status = "Sent"`）
     - 即使成员不在线，状态记录也会被创建，确保上线后能正确统计未读数量
     - 成员上线后，打开会话时会标记已读，更新状态记录为 `Status = "Read"`
     - 每条消息+每个成员一条状态记录（`MessageId` + `UserId` 唯一）

10. **未读计数准确性**：
    - **私聊消息**：基于 `MessageStatus` 表查询，接收方是当前用户且没有 `Status = "Read"` 记录的消息
    - **群组消息**：基于 `MessageStatus` 表查询，群组ID匹配且发送方不是当前用户，且（没有状态记录 || 有状态记录但状态不是Read）的消息
    - 离线期间的消息会被正确计入未读数量（私聊和群聊）
    - 上线后打开会话时，未读计数会清零（自动标记已读）
    - 群组消息的状态记录在发送时已创建，确保离线成员上线后能正确统计未读数量
